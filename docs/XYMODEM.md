# XMODEM / YMODEM 文件传输

XMODEM 和 YMODEM 的握手字节也可能出现在普通终端输出中，因此 QShell 不会脱离命令上下文识别协议。在终端中直接输入或粘贴并提交 `rx`、`sx`、`rb` 或 `sb` 命令时，QShell 会识别裸命令和带路径的命令。`rx`、`rb` 会在远端握手确认命令已经启动后打开文件窗口；`sx`、`sb` 会短暂等待远端的“命令不存在”等错误，确认没有立即失败后再打开窗口。

通过别名或脚本间接启动传输时，仍可使用 `File` 菜单中的“文件传输”入口。非英文或非常规 shell 的错误提示可能无法识别，此时传输仍会按超时机制结束。

BusyBox 通常只提供 XMODEM 接收端 `rx`，可以使用 `busybox rx 目标文件名`、`/bin/busybox rx 目标文件名`，也可以使用已安装的独立 `rx` applet 链接。BusyBox 构建未包含 `rx` applet 时不会弹出文件窗口；`sx`、`rb`、`sb` 仍需由 lrzsz 等其他工具提供。

## XMODEM

XMODEM 不传递文件名，每次只能传输一个文件。

### 发送到远端

1. 在远端执行 `rx 目标文件名`。
2. 在自动打开的窗口中选择一个本地文件。

发送端会根据远端握手自动使用校验和或 CRC16，数据使用兼容性较高的 128 字节块。

### 从远端接收

1. 在远端执行 `sx 文件名`。
2. 在自动打开的窗口中选择本地保存文件名。

接收端先请求 CRC16；如果远端不响应，会回退到校验和。接收支持 128 字节 XMODEM 块和 1024 字节 XMODEM-1K 块。

XMODEM 不携带原始文件大小。QShell 接收时会按传统方式删除最后一块末尾的 `0x1A` 填充字节，因此无法无歧义地保留源文件本身末尾的连续 `0x1A`；向其他实现发送时，是否删除填充由对端决定。

## YMODEM

YMODEM 会传递文件名和文件大小，并支持一次传输多个文件。

### 发送到远端

1. 在远端执行 `rb`。
2. 在自动打开的窗口中选择一个或多个本地文件。

### 从远端接收

1. 在远端执行 `sb 文件1 文件2 ...`。
2. 在自动打开的窗口中选择本地保存目录。

同名文件不会被覆盖，QShell 会为新文件添加编号。文件先写入同目录的临时文件，完整接收并通过 CRC16 校验后才提交。

## 传输控制

- 进度窗口显示当前文件和批次进度。
- 点击“取消”或在传输期间按 `Ctrl+C` 会通知远端终止传输。
- 支持坏块重传、重复块确认、超时和远端取消。
- XMODEM / YMODEM 可用于 SSH、串口和本地终端会话。
